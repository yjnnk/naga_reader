# NagaReader Usability Evolution Spec

## Problem Statement

The user can now read EPUBs in NagaReader, but the app still feels like a development build rather than a daily macOS reading tool. The user has to launch it from Terminal, cannot choose a preferred reading font, and keyboard reading controls are incomplete for a mouse-free reading flow.

The user wants the next evolution to make NagaReader easier to open from Finder, more comfortable for long reading sessions, and controllable from the keyboard in both paginated and scrolling modes.

## Solution

Add three small usability features:

1. Build and install a local `NagaReader.app` bundle in `~/Applications`, generated by a versioned script.
2. Add a short, curated font selector to the reading appearance menu and apply the selected font to rendered EPUB content.
3. Expand keyboard navigation so page turns, scrolling, and chapter boundary transitions work naturally without using the mouse.

This remains a personal local macOS app. Public distribution, signing, notarization, and installer polish are intentionally deferred.

## User Stories

1. As the reader, I want to find NagaReader in Finder, so that I do not need to launch it from Terminal.
2. As the reader, I want NagaReader to live in my user Applications folder, so that it behaves like a normal personal Mac app.
3. As the reader, I want a repeatable build command, so that the Finder app can be regenerated after code changes.
4. As the reader, I want the build command documented, so that I can rebuild or reinstall the app without remembering implementation details.
5. As the reader, I want the app bundle to have a correct executable and metadata, so that macOS can open it like a normal app.
6. As the reader, I want the app bundle to avoid admin installation, so that setup stays simple on my machine.
7. As the reader, I want to choose a reading font, so that long reading feels more comfortable.
8. As the reader, I want a small curated font list, so that the appearance menu stays minimal.
9. As the reader, I want sensible reading fonts, so that I do not have to evaluate every installed system font.
10. As the reader, I want the selected font to persist, so that the app remembers my preference after reopening.
11. As the reader, I want the selected font to apply to EPUB body text, so that the reading view actually reflects the setting.
12. As the reader, I want the selected font to work with existing size, line-height, margin, width, mode, and theme settings, so that typography settings compose cleanly.
13. As the reader, I want a System default font option, so that I can return to a native macOS reading feel.
14. As the reader, I want serif reading options, so that long-form prose can look book-like.
15. As the reader, I want a monospace option, so that technical EPUBs remain readable when desired.
16. As the reader, I want right arrow to advance in paginated mode, so that I can read without clicking.
17. As the reader, I want left arrow to go back in paginated mode, so that correction is quick.
18. As the reader, I want Space and Page Down to advance in paginated mode, so that common reading keys work.
19. As the reader, I want Shift-Space and Page Up to go back in paginated mode, so that common reverse navigation works.
20. As the reader, I want down arrow to advance in paginated mode, so that vertical reading keys also work.
21. As the reader, I want up arrow to go back in paginated mode, so that keyboard behavior is predictable.
22. As the reader, I want down arrow, Space, and Page Down to scroll down in scrolling mode, so that scrolling mode is usable from the keyboard.
23. As the reader, I want up arrow, Shift-Space, and Page Up to scroll up in scrolling mode, so that I can reverse in scrolling mode.
24. As the reader, I want the next-page action at the end of a chapter to open the next chapter, so that reading continues naturally.
25. As the reader, I want the previous-page action at the beginning of a chapter to open the previous chapter, so that I can move backward naturally.
26. As the reader, I want chapter transitions to work from the visual pagination buttons, so that mouse and keyboard navigation follow the same rules.
27. As the reader, I want chapter transitions to preserve expected position, so that next chapter opens at the beginning and previous chapter opens at the end.
28. As the reader, I want keyboard shortcuts to avoid interfering with text selection or standard system behavior unnecessarily, so that the reader still feels native.
29. As the reader, I want the app to remain single-window and minimal, so that these features improve the existing flow rather than adding complexity.

## Implementation Decisions

- Generate a local macOS app bundle rather than creating an Xcode project immediately.
- Install the generated app bundle into `~/Applications/NagaReader.app`.
- Add a versioned build script that runs the Swift build, creates the `.app` bundle structure, writes the bundle metadata, copies the executable, and installs the app in the user Applications folder.
- Keep public distribution work out of this cycle: no App Store packaging, no notarization, no signed installer, and no DMG requirement.
- Document the local app build/install command in the project README.
- Add a `fontFamily` reading setting to the existing global reading settings model.
- Preserve backward compatibility for existing settings files by defaulting missing font data to the recommended font choice.
- Use a curated font list rather than a full system font picker.
- Start with these choices: System, New York, Georgia, Athelas, Palatino, Charter, Iowan Old Style, and Menlo.
- Apply the selected font through the controlled reading document CSS, using fallback stacks where appropriate.
- Keep the appearance menu as the control surface for font selection.
- Treat keyboard input as reader navigation, not global app commands.
- Keep the existing paginated WebView as the input point for page-level keyboard events where appropriate.
- Add chapter-boundary navigation through the reader state layer, so WebView page movement can request "next chapter" or "previous chapter" when it cannot move further within the current chapter.
- In paginated mode, right arrow, Space, Page Down, and down arrow advance; left arrow, Shift-Space, Page Up, and up arrow go backward.
- In scrolling mode, down arrow, Space, and Page Down scroll down; up arrow, Shift-Space, and Page Up scroll up.
- At the end of a chapter, an advance action opens the next chapter at progress `0`.
- At the beginning of a chapter, a back action opens the previous chapter near its end.
- The visual pagination buttons use the same navigation semantics as keyboard pagination.

## Testing Decisions

- Good tests should verify user-visible contracts and stable module behavior, not private implementation details.
- The app-bundle feature should be tested at the script/artefact level: the generated bundle contains a valid macOS bundle shape, bundle metadata, and executable path.
- The font feature should be tested through the existing reading settings and document building seams.
- Settings tests should verify that font selection persists and older settings data without a font still loads with a default.
- Document builder tests should verify that the selected font appears in the generated reader CSS with the expected fallback behavior.
- Navigation tests should prefer the highest model seam available: a reader/session or view-model level command that can move to next and previous chapters at boundaries.
- WebView-specific keyboard handling should be covered by a light JavaScript/AppKit contract where practical and by manual QA, because it depends on real focus and WebKit behavior.
- Existing prior art includes tests for `ReadingSettingsStore`, `ReadingDocumentBuilder`, `ReaderSession`, and reading position persistence.
- Manual QA should include opening the real Ultralearning EPUB, selecting multiple fonts, switching between paginated and scrolling modes, and using keyboard controls at the beginning, middle, and end of chapters.

## Out of Scope

- App Store distribution.
- Code signing and notarization.
- DMG or `.pkg` installer.
- Custom app icon polish beyond what is required for a functional local bundle.
- Full system font picker.
- Per-book font settings.
- Per-book keyboard shortcut customization.
- Highlighting, annotations, search, sync, or library management expansion.
- Multi-window reading.
- Animated page turns.

## Further Notes

These features are intentionally small but important for making NagaReader usable as a daily personal app. The preferred implementation order is:

1. Local app bundle script and README.
2. Font selection setting and rendering.
3. Keyboard navigation and chapter boundary movement.

The features should be converted into three implementation tickets in that order.
